# 功能備忘錄：形態辨識、訊號交叉比對、參考價

2026-10-26 記。還沒實作。

## 需求

1. 系統能辨識技術形態，並給出解析。
2. 依不同市場訊號交叉比對後再判斷。
3. 如果可以，加一個參考價。

## 現況：LLM 怎麼判斷漲跌

**LLM 目前不判斷漲跌。** 方向全部來自程式算好的統計標籤，LLM 只負責讀和轉述。

| 地方 | LLM 的工作 | 看得到的價格資訊 | 方向從哪來 |
|---|---|---|---|
| `llm_trader.py` | 對量化候選說 buy / skip / wait | `analyst.stock_facts` 事實表 | 不判斷方向，只判斷「這檔值不值得買、現在還是再等」 |
| `report.py` 摘要 | 寫個股報告文字 | 同上 | prompt 明寫「看漲 / 看跌只能用 outlook 的模型標籤，不要自己另外判斷方向」 |
| 分析師問答 | 回答問題 | 同上，加 `price_performance` 等工具 | 同上 |

事實表的 `price` 章節只有摘要數字：收盤、1/3/6/12 個月報酬、52 週高低、距 52 週高點、相對 200 日均線、60 日年化波動、一年最大回落、20 日均成交值。**LLM 看不到日 K 序列，也看不到個別技術訊號。**

方向標籤（`outlook.py`）：

- 短期（20 日）：`triple_ma`、`px_ma21`、`macd`、`from_high` 四個訊號各轉百分位後平均，≥80 看漲、≤20 看跌。
- 中期（60 日）：綜合分數。
- 長期（250 日）：品質 + 價值。
- 每個標籤附樣本外（2019 起）的歷史校準與可靠度。

`technicals.py` 其實算了約 20 個訊號（均線穿越、黃金交叉、MACD、CCI、RSI、KST、布林 %b、量能放大等），但只用在回測，最新一天的值沒有存下來，也沒有給 LLM。

所以對照三個需求：

- **形態辨識**：沒有。只有均線、指標類訊號，沒有 W 底、頭肩、箱型、旗形這類價格形態。
- **交叉比對**：只有「同一期間內的訊號取平均」。沒有跨維度（技術、籌碼、基本面）的一致或矛盾檢查；LLM 讀事實表時會自己比對，但沒有規則、也沒驗證過。
- **參考價**：沒有。三個 prompt 都明文禁止目標價。

## 提案

原則和現有設計一致：**數字由程式算、有回測校準，LLM 只解讀，不自己生數字。**

### 1. 形態辨識 `patterns.py`

- 規則式偵測，不讓 LLM 看圖猜形態。資料用 `prices_daily.parquet`（有 OHLC、成交量）。
- 第一批候選形態：
  - 帶量突破：收盤創 N 日新高，且成交值 > 60 日均量 × k
  - 箱型整理：近 N 日高低區間 / 收盤 < x%，標出箱頂、箱底
  - W 底 / M 頭：兩個相近低點（高點）與中間頸線，突破頸線才成立
  - 回測均線：多頭排列中拉回到 21 / 60 日線附近
  - 跳空缺口：開盤跳過前日高（低）點，記缺口價位
- 每個形態輸出：成立日、關鍵價位（頸線、箱頂底、缺口）、和 `technicals.py` 一樣的回測校準（產業中性超額、Newey-West t、2011–2018 / 2019– 兩段）。
- `technicals.py` 現有訊號也一併把「最新一天的值」存下來，讓事實表能引用。
- 預期：`technicals.py` 已經發現反轉類訊號樣本內不顯著，傳統形態很可能也大多沒有預測力。**沒通過校準的形態照樣顯示，但標「歷史上不可靠」**，不能當買賣理由。

### 2. 訊號交叉比對

- 做一張訊號矩陣，四個維度各給 多 / 空 / 中性：
  - 技術：短期標籤 + 成立中的形態
  - 籌碼：外資、投信近 5 / 20 日買賣超、融資變化
  - 基本面：月營收動能、毛利率變化
  - 綜合：中 / 長期標籤
- 輸出「一致數」與「矛盾清單」，例如「短期看漲，但外資連 10 日賣超」。
- 要回測「一致數高」是否真的比單看綜合分數好；組合方式很多，每試一種都記進 `data/strategy/trials.jsonl`，避免事後挑最好看的。
- LLM 的解析只能引用矩陣與矛盾清單，不自己另外下結論。

### 3. 參考價

全部用公式算，LLM 不給價格。三種，標清楚意義：

| 名稱 | 算法 | 意義 |
|---|---|---|
| 支撐 / 壓力 | 21 / 60 / 200 日均線、箱頂箱底、頸線、52 週高點中，離現價最近的上下各一個 | 技術面常用價位，不是預測 |
| 停損參考 | 收盤 − 2 × ATR(14)（OHLC 已有） | 風控用，配合持有期 |
| 統計波動區間 | 現價 × (1 ± 60 日年化波動 × √(H/244))，H = 20 或 60 | 約 68% 的機率範圍，**不是目標價** |

- 統計區間要回測：歷史上實際落在區間內的比例，接近 68% 才算校準得好。
- 名稱用「參考價 / 參考區間」，不叫「目標價」；頁面和報告都加同一段免責說明。

## 要注意

- **不要動 `llm_trader.py` 的 prompt 和事實表。** 前向實驗 2026-10-22 那批才開始，改了 `PROMPT_HASH` 就會前後條件不一致。新功能先放在 `report.py`、分析師問答和前端；要測 LLM 有沒有因此選得更好，另開一組（例如 `LLM篩選-haiku-形態`），和原組並行。
- prompt 目前禁止目標價，加參考價時要一起改規則：LLM 只能引用程式算的參考價，不能自己推算。
- 形態和交叉比對都會增加嘗試次數，樣本外證據要用 2019 之後、甚至 2024 之後分段看。

## 建議順序

1. `technicals.py` 存最新訊號值 + `patterns.py` 偵測與校準
2. 參考價（支撐壓力、ATR 停損、統計區間）與區間校準
3. 訊號矩陣與矛盾清單，接到事實表的新章節
4. 個股頁、報告顯示；`report.py` prompt 改成可引用
5. 視結果決定要不要另開 LLM 實驗組
