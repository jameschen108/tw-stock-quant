## 1. 修正：依排序分數加權時，權重方向相反

- **問題**：`strategy.target_weights` 用 `weighting = "score"` 時，排名第一的股票拿到的權重反而最小（例：三檔分數 90／50／10，權重變成 0.167／0.333／0.5）。
- **修正**：名次改成 `rank(ascending=not asc)`，排在前面（選股時先取）的權重大。
- **影響**：只有用 score 加權的策略會變；預設等權的不受影響。附測試 `test_score_weighting_favors_top_ranked`。

## 2. 策略：新增停利與持有天數出場

- `[risk]` 新增兩個鍵，預設關閉：
  - `take_profit`（例 0.30）：個股從進場價漲超過這個幅度就賣。
  - `max_hold_days`（例 60）：持有滿這麼多個交易日就賣。
- 和停損一樣是每天收盤判斷、隔天收盤賣，這一期不再買回。
- 放在 `LATE` 裡，**沒用到時舊策略的設定雜湊不變**，過去的回測結果和嘗試紀錄都不受影響。
- 回測的買賣明細原因會分別標成「停利」「持有期滿」，不會被算成「停損」。
- 策略頁「線上試跑」可以直接設定這兩個值。

## 3. 自選組合：名單來源、加權方式、風險規則

原本自選組合只能自己輸入代號和權重、買進持有或每月調回。現在建立時可以選：

| 設定 | 選項 |
|---|---|
| 名單來源 | 自己輸入、觀察名單、模型選股（短中長期都看漲）、`strategies/*.toml` 的選股條件；可每月照同一規則重選 |
| 加權方式 | 照輸入的權重、等權、波動倒數（波動小的多買）、綜合分數高的多買；可設單檔上限 |
| 風險規則 | 停損（從進場價或從高點）、停利、持有天數、大盤濾網（0050 或全市場等權跌破均線降部位）、資產回落控制、目標波動 |

- 規則存在 `mine_meta.json`，**沒用到的欄位不寫**，舊的組合設定和以前完全一樣。
- 重播時規則照樣帶進 `strategy.simulate`，成本、零股、漲跌停規則和回測相同。
- 規則建立後不能改（要換規則就建新組合），避免回頭改到過去的淨值。
- 指令：`uv run mine.py new 低波 2330,2317,2454 --weighting inv_vol --max-weight 0.4 --rule stop_loss=0.1 --rule regime=ma`

## 4. 自選組合：財報驚喜事件名單（新檔 `surprise.py`）

把我們研究過的「財報公布後追價」規則（盈餘驚喜相關文獻的價格漂移）接到這套系統的資料上。

- **驚喜分數**：跟公司自己的過去比，不是跟分析師預估比。
  - 月營收：（本月營收 − 去年同月）相對過去 24 個月同樣差額的標準化值。
  - 盈餘：單季歸屬母公司淨利的同樣算法，用過去 8 季。
- **分組**：只看上市普通股、成交量不在最低 20% 的公布事件。用公布月份之前 12 個月的事件分 10 組，最高一組 = 驚喜，最低一組 = 壞消息。
- **進出場**：公布日隔一個交易日收盤買進；月營收持有 20 個交易日，盈餘持有 60 個交易日。
- **公布日**：用 `tej_rev` / `tej_fin` 的 `avail_date`，推估出來的公布日不算。
- **自選組合的名單來源多兩個**：「月營收驚喜」「盈餘驚喜」。每天 `update.py` 跑 `mine.py` 時，名單有變就記一期：新公布的買進、持有期滿的賣出，名單空了就留現金。已持有的股票偏離目標不到半個單位就不調，省手續費。
- 單獨看名單：`uv run surprise.py`（月營收）、`uv run surprise.py --kind eps`（盈餘）、`--bad` 看壞消息。

**驗證**（規則是研究時事先寫定的，這裡沒有重新調參數）：

| | 月營收驚喜 | 盈餘驚喜 | 0050 |
|---|---|---|---|
| 2018–2025 年化（扣成本） | +20.9% | +20.7% | +20.0% |
| 2026 年 1～9 月 | +45.5% | +38.9% | +64.5% |

- 研究時的結論是**每年都贏一般股票，但沒有贏 0050**，這裡的結果一致。
- 不扣成本時月營收是 +38.1%／年。成本吃很多，因為持有 20 天、一年換手約 30 倍。
- 名單和我們研究用的版本比對：月營收目前持有的 115 檔完全相同；盈餘最高組 96% 相同（差在門檻的歷史長度）。

## 5. 自選組合：建立前先回測過去

- 「建立新組合」多一個「先回測過去」按鈕（預設 3 年）。用同一套名單來源、加權方式、風險規則，從起日開始回頭重播。
- 每個訊號日只用當時的資料重選、算權重；月調的訊號日是每月最後一個交易日，財報驚喜是名單有變的日子。
- 有風險規則時，另外跑一次「不加風險規則」對照，看規則到底有沒有幫助。
- 結果顯示淨值圖和比較表（這套規則、不加風險規則、同組等權、0050），不寫任何檔案。
- 名單是自己輸入或觀察名單時會提醒：名單是現在挑的，回測過去有後見之明。
- 指令：`uv run mine.py bt - --source rev_surprise --weighting equal --start 2023-01-01`

## 6. 修正：前端「更新 / 重算」在 Windows 上無法執行

- **問題**：`frontend/common.py` 的 `_run_job` 用 `fcntl` 防止同時跑兩個指令，Windows 沒有這個模組，按任何一個按鈕都會 `ModuleNotFoundError`。
- **修正**：Windows 改用 `msvcrt` 鎖檔，Mac／Linux 照舊用 `fcntl`；子程式輸出固定用 UTF-8 讀，中文才不會變亂碼。
